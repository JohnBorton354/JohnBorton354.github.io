About

I'm a senior systems and software test automation engineer in defense, with a dual background in CS and Statistics and a physics minor that taught me to care about measurement. I design automation architectures that simulate operator inputs and the external environment, capture the resulting system data, and run queued analysis pipelines to verify that complex systems behave as intended. I also mentor engineers on automation practices and design.

I'm now pursuing an MS in Analytics at Georgia Tech, and I'm bringing the same rigor to data engineering, machine learning, and data science.

Testing Pipeline

A simplified look at how I validate a system end to end:

(Tap to see more)

01 Scheduling

Trigger and schedule test runs automatically, via CI/CD or job queues, with no manual kickoff.

→
02 Operator & Environment Inputs

Automate operator inputs and the external environment with scripted, repeatable scenarios.

→
03 System Under Test

The system itself: its behavior is driven entirely by the automated inputs and environment around it.

→
Live Stream ⇢

When live results matter or time is limited, system data from step 4 can stream directly to the dashboard in step 6, skipping job-queued analysis.

04 Data Collection

Capture the system data generated during each test run.

→
05 Job-Queued Analysis

Queue the collected data through automated pipelines to validate behavior at scale.

→
06 Presentation / Dashboard

Validate results against requirements and present them in a dashboard built for stakeholders and reviews.
